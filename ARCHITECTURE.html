Webcam to VNC

Node B sends its camera to the server on node A. Anyone viewing the VNC desktop can then open it in ffplay.

How it works

  1. Sign in. Node B logs in to auth-proxy and gets a session cookie that every webcam route checks.
  2. Signal. The page posts a WebRTC offer to /api/webcam/offer. auth-proxy closes any earlier sender, creates the receiver and answers with node A's real address, because the container's own address is not reachable from node B.
  3. Stream. The video goes straight to auth-proxy over UDP 50000–50009, not through the HTTPS port.
  4. Write the camera. Each frame is scaled to 640×480 and sent to the kasmvnc container, where ffmpeg writes it into /dev/video0.
  5. Watch it. ffplay -f v4l2 /dev/video0 in a terminal inside the VNC desktop shows the camera. The session is shared, so every viewer sees the same window.
Run ffplay inside the VNC desktop. On node A's own host terminal it opens on node A's physical screen, not in VNC. The camera works only while node B's /webcam page is streaming, and only one sender is active at a time.
